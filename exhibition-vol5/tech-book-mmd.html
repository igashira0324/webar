01. COVER / 概要

本プロジェクト「MMD × WebXR Experience」は、Webブラウザという「最も普及し、最も制限された」プラットフォーム上で、どこまで高品質なキャラクター体験を実現できるかという挑戦から始まりました。従来のAR体験は、専用アプリのダウンロードという高い壁がありましたが、本システムはそれを完全に排除。来場者は手元のスマートフォンでQRコードを読み取るだけで、即座にミクの世界へと引き込まれます。

この実現には、単なる3D表示だけではなく、現実の空間構造をリアルタイムで解析する「環境理解」、物理法則に従って髪や服を揺らす「剛体シミュレーション」、そして視聴者の位置に同期した「立体音響」の3要素を、限られたモバイルリソース内で完璧に同期させる必要がありました。本書では、その裏側にある泥臭い最適化と、数学的な美しさを伴うアルゴリズムを詳らかにします。

03. TECH STACK

システムの心臓部には、Viteによる高速なホットリロード環境と、TypeScriptによる厳密な型定義を採用しています。3D演算において最も恐ろしいのは、行列演算の誤りによる「モデルの消失」です。これを静的解析で未然に防ぐことで、開発速度と品質を劇的に向上させました。

描画エンジンにはBabylon.jsを選択。その理由は、WebXRへの対応の早さと、シェーダーの柔軟なカスタマイズ性にあります。MMD特有のトゥーンレンダリングをWebXRのライト推定（Lighting Estimation）と組み合わせるため、独自のカスタムシェーダーマテリアルを開発しました。また、物理演算にはBullet PhysicsをWebAssembly化したAmmo.jsを使用。これにより、毎フレーム数千個のボーンと剛体の相互作用を計算することが可能となりました。

06. MMD IMPLEMENTATION

MMDモデル（PMX）のロードには、単なる3Dメッシュの読み込み以上の処理が含まれます。各頂点に設定されたボーンウェイト、SDEF（Spherical Dual Quaternion Skinning）による関節の変形、そして何より重要な「表情モーフ」の制御です。

// IK (Inverse Kinematics) の計算ロジック抜粋
for (let i = 0; i < ikChain.length; i++) {
  const bone = ikChain[i];
  const targetPos = target.getWorldPosition();
  const currentPos = bone.getWorldPosition();
  // CCD (Cyclic Coordinate Descent) アルゴリズムによるボーン回転の収束
  solveIK(bone, targetPos, currentPos);
}

物理演算においては、Ammo.js上で「剛体」「ジョイント」「スプリング」の3要素を構成。MMD特有の「物理演算の焼き付き」を防ぐため、Babylon.jsのレンダリングループとAmmo.jsのステップ実行を厳密に同期（Fixed TimeStep）させています。これにより、激しいダンスモーションでも服が突き抜けたり、髪が暴走したりすることのない安定した描画を実現しました。

10. DESIGN DECISIONS

開発過程で最も苦慮したのは、テクスチャの容量問題です。MMDモデルは数多くの高解像度テクスチャ（BMP/PNG）を使用しますが、モバイル通信環境ではこれが大きなボトルネックとなります。本プロジェクトでは、すべてのテクスチャをGPUフレンドリーなKTX2形式に事前に圧縮・変換し、さらにBasisu技術を用いることで、画質を維持したままデータ量を約1/4に削減しました。

⚡ GPU OPTIMIZATION: KTX2はGPUが直接解凍・参照できる形式であるため、VRAMへのロード時間がほぼゼロになり、ブラウザのメインスレッドがフリーズする問題を完全に解決しました。
